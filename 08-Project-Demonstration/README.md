# Project Demonstration

## Project Title

Auto Ticket Classification using Flow Designer

## Project Demonstration

This phase demonstrates the complete working of the Auto Ticket Classification using Flow Designer project.

The demonstration explains the purpose of the project, the working process, automatic ticket classification, and the final output.

## Purpose of the Project

The purpose of this project is to automatically classify school IT support tickets based on the issue description.

The system reduces manual effort and improves ticket routing efficiency.

## Project Benefits

The project provides the following benefits:

- Automatic ticket classification
- Reduced manual effort
- Improved ticket routing
- Consistent Category and Subcategory assignment
- Automated email notification
- Easy maintenance using Flow Designer

## Working Process

The project works in the following steps:

1. A student or teacher creates an IT support ticket.
2. The Caller information is entered.
3. The issue is entered in the Short Description field.
4. The ticket is submitted.
5. Flow Designer is automatically triggered.
6. The Short Description is checked for predefined keywords.
7. Category and Subcategory are automatically assigned.
8. An email notification is sent to the caller.

## Demonstration Scenarios

### Scenario 1 - Wi-Fi Issue

Input:

WiFi not working in library

Expected Output:

Category: Network

Subcategory: Wi-Fi

### Scenario 2 - Projector Issue

Input:

Projector not turning on

Expected Output:

Category: Hardware

Subcategory: Projector

### Scenario 3 - Password Issue

Input:

Forgot Password

Expected Output:

Category: Access

Subcategory: Forgot Password

### Scenario 4 - Slow Computer Issue

Input:

Slow Computer

Expected Output:

Category: Performance

Subcategory: Slow Computer

## Final Output

The system successfully classifies the IT support ticket based on the Short Description.

The appropriate Category and Subcategory are automatically assigned.

An email notification is also sent to the caller after the ticket is created.
